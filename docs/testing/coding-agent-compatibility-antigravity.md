# Antigravity (agy) compatibility test matrix

For users and maintainers who need an auditable record of what was actually tested against the Antigravity CLI, when, on which code version and OS, and with what result. After this page you know which Antigravity behaviors are verified and the evidence behind each result.

This is the first per-coding-agent compatibility matrix (issue [#1545](https://github.com/mblua/AgentsCommander/issues/1545)). Planned future files for **Claude, Codex, Pi, Hermes, Cursor CLI, and OpenCode** follow the same template in [coding-agent-tests-template.md](coding-agent-tests-template.md); they are not created yet.

## How to read this matrix

- **Result** is `PASS` only when an actual run observed it, and it names the evidence kind: `live` (smoke run against a real daemon), `unit` (test suite), `manual`, or `CI`. Rows without an actual run are **PENDING** — never treat a PENDING row as verified.
- **Code version** pins the exact build each result was observed on — for example `v0.30.1 (d64e6250)` — or the build a PENDING row must use when it is run. A result without a code version is not reproducible.
- **Date (UTC)** and **OS** are recorded per row. Current test host: **Windows 11 Pro, build 10.0.26200**.
- **Notas** carries the caveats, context, and failure reasons that make the result interpretable.
- The smoke-era live evidence (the "Agent identity/detection" and "PTY injection wake" rows) ran against the daemon that predated merge `d64e6250`. Every other live result in this file was observed on the v0.30.1 (`d64e6250`) daemon or on post-#1549 main (`92afbfe6`); each row pins its own code version.
- **Catalog drift — update commands:** the update-related rows record the pinned daemon v0.30.1 (`d64e6250`), whose embedded catalog defined `updateCommands: []` for agy. Current main (post-PR #1548, commit `5147c5ad`) defines `updateCommands: ["agy update"]`, and that flow is not live-tested yet. Read the update rows as the `d64e6250` state, not the current main catalog.

Decisión para vos: ¿dónde deberían vivir los controles de movimiento — solo en Settings, solo en Step 1, o en ambas?

Cambios de producto más allá de las capturas confirmadas

Estos comportamientos no se ven en las dos capturas que confirmaste. Con el resaltado activo, cada punto lleva su número en ámbar sobre la pantalla correspondiente.

1Step 1 usa el orden compartido y deja de ordenar alfabéticamente.
2Mover guarda el orden de inmediato y de forma acotada: sin botón Save y sin reescribir toda la configuración.
3Mover no guarda el borrador de Settings: una edición de color sin guardar sobrevive al movimiento.
4Reglas de movimiento y teclado: una posición adyacente; primero-arriba y último-abajo deshabilitados; Tab/Enter/Espacio; foco, selección y rail conservados por id de herramienta.
5Regla de filtro: el filtro oculta tarjetas de Step 1 y desactiva solo sus movimientos; Settings sigue habilitado; la comparación mantiene el orden completo.
6Propiedad de settings.local.json: los controles de movimiento se deshabilitan con un motivo accesible (comportamiento propuesto; depende de un flag de backend que la app hoy no expone).
7Propiedad iniciada después de cargar: el lado del comando rechaza el movimiento y revierte.
8Fallo de guardado transitorio: el orden se revierte y se ofrece reintento.
9Vecino esperado obsoleto: se adopta el orden del otro escritor y se explica; el movimiento pedido no se aplica.
10Valor numérico order por herramienta en settings.json.agents[] (entero, base 0): un solo orden global; un movimiento desde Settings o Step 1 actualiza los valores y ambas vistas; al guardar se normaliza a 0..n−1; si el campo falta se deriva del array y si un valor es inválido se cae a la posición del array y se avisa.

Persistencia simulada — settings.json.agents[].order Solo prototipo10

Un solo orden global. Cada herramienta lleva el entero base 0 que define su posición; un movimiento desde Settings o desde Step 1 actualiza estos valores y ambas vistas de inmediato. Si el archivo no trae el campo, el orden se deriva del array; al guardar se normaliza a 0..n−1; un valor inválido cae a la posición del array y avisa. Los valores corresponden al orden compartido propuesto. Simulado: el prototipo no escribe ningún archivo real.

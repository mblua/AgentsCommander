Naming suggestions for hand-editing
letters
profileSlots
“letters” doesn’t say what it holds — these are the profile slots keyed A/B/C/D.
letters.*.name
label
“name” reads like an id; it’s the human display label of the profile.
matrix
profilesByAgent
“matrix” is abstract. The data is per-agent profile definitions: agentId → letter → cell.
matrix.*.*.argv
args
“argv” is C/Unix jargon. “args” is plainer for a human editing a list of flags.
agentDefaults
defaultProfileByAgent
Clarifies the map: agentId → its default profile letter.
tooling.instanceProfileOverride
tooling.profile
Under per-replica tooling, “profile” is enough; “instance…override” is internal jargon.
isolateCodexHome
isolatedHome
Drop the codex-specific name so the flag reads on any coding agent.
envs[].source: "agentsCommander"
source: "system"
Shorter, and a clearer opposite of “user”.
Why this shapedesign note
• One global store — settings.json holds agent definitions + the profile table. Plain JSON, pretty-printed, safe to edit by hand.
• Sparse table — only configured cells exist; a missing letter falls back per agentDefaults, so the file stays small.
• Tiny per-replica override — “Assign to this replica” only writes a 2-line tooling block; broad-scope actions repeat that write across many replicas.
• schemaVersion stays — it lets future migrations rename fields safely (renames above would bump it).

09 | Failure and retry rules

Uncertainty is state to inspect, never permission to retry

Before POST, still exact 404

No Release mutation exists. Review the cause and confirm no prior recovery crossed POST. A new main dispatch or later attempt may re-enter fresh only through the full classifier.

Admin read or evidence differs

Stop before the next mutation. Never fall back to the normal token, another credential, cached data, or an assumption.

POST invoked, response uncertain

Query once. Exact immutable success may enter read-only resume; every draft, partial, or ambiguous state blocks. Never issue a second POST.

Build or assembly fails after POST

Leave the confirmed mutable draft untouched. No delete, clobber, partial upload, repair, or blind rerun. Require a separate owner-reviewed decision.

Draft asset mismatch

Duplicate, partial, extra, zero-byte, pending, unexpected, or wrong-digest asset stops before publication. Never repair one asset in place.

PATCH invoked or uncertain

Query exact state first. Exact immutable success continues read-only; an exact draft or any mismatch blocks. Never blindly repeat PATCH.

Immutable success, evidence fails

A later run can enter only exact read-only resume, reconstruct by numeric asset ID, and retry verification/evidence retention.

Immutable identity differs

The version cannot be repaired in place. Stop and plan a new version. Never delete, recreate, reupload, or retag.

Universal post-mutation rule: query exact external state first. Do not rerun, rebuild, reupload, retag, delete, recreate, republish, or roll back from an uncertain result.

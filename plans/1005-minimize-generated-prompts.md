## 4. Rewrite methodology (task item 2)

Applies to every text in every stage. Dev-rust produces wording; grinch gates it; architect gives the consensus verdict per FULL flow.

**Per-text procedure:**

1. **Semantic inventory (from the OLD text).** Numbered list; one row per atomic statement, classed as: RULE (prohibition/obligation), GRANT (permission), IDENTITY (who the agent is / what a thing is), AUTHORITY (who may order what), PROCEDURE (ordered step), ANCHOR (machine-coupled exact string: heading, command line, filename pattern, wire format, path placeholder). Row atomicity rule (G1): qualifiers that scope a rule or grant (e.g. "always identified as the registered `settings.projectPaths` entry") are their own rows, never absorbed into the parent statement's row.
2. **Rewrite** under the criterion. Hard rules:
   - Every ANCHOR row stays byte-identical (see keep-exact lists in section 5).
   - Precedence when constraints collide (TL3/G5): **ANCHOR byte-identity > em-dash-free (where test-pinned) > brevity.** Em-dash-pinned targets that must stay U+2014-free: `ROOT_PROJECT_SCOPE_ENTRY`, `ROOT_PROJECT_SCOPE_ALLOWED`, `ROOT_AUTHORITY_SECTION`, `SELF_MAINTENANCE_AUTO_SECTION` (test :4810-4814), the C2 prompts (mailbox tests), and the coordinator template (test :6289-6292). Keep-exact anchors that CONTAIN em-dashes and must survive any sweep: the A6 per-repo line format (:1343, :1351, :1385, :1395), the B3 provenance comment (:360), the "Narrow exception" headers, and the frozen legacy corpus. Each stage checklist carries its em-dash constraint map: (a) pinned-free targets, (b) surviving keep-exact em-dashes, (c) tests whose current needles carry em-dashes (S3: :4316, :4360, :4390, :4658, :4702, :4848).
   - Strength words carry normative force: MUST / NEVER / ONLY / "ABSOLUTE AND NON-NEGOTIABLE" survive or are replaced by equal-or-stronger forms, never weakened.
   - No new synonyms for defined terms (replica, Agent Matrix, workgroup, Root Agent, workspace root, canonical state).
   - Redundancy may be cut only when a surviving row carries the identical normative force for the identical scope. Restating-for-emphasis is the main cut class (the Allowed bullets vs the numbered grants; git ceiling stated twice; repeated warnings).
   - Dynamic `format!` placeholders and their delimiters (code fences around paths) survive unchanged.
   - Match repo text conventions (the generated texts use em-dashes and bold markers; keep the existing style, just less of it), subordinate to the precedence rule above.
3. **Mapping table.** Every old row -> quote of the new text satisfying it, or `DROPPED: duplicate of row N` naming the surviving row. A row may never be dropped without a surviving carrier. The REMOVED class (intentional semantic removal with tech-lead sign-off) exists in the format but has NO instances in this project: TL2 converted the only candidate (A9 screenshot bullets) to compressed-in-place.
4. **Anchor phrases for tests.** Harvest FIRST (E3): before rewriting, grep every string-literal needle in the affected test range and treat short operative needles as pre-designated anchors to be kept verbatim in the new wording (those tests then do not change at all). Em-dash-carrying needles are filtered out of the harvest up front (G5); they get new anchors. For rules without a harvested needle, the rewriter designates a short stable anchor phrase inside the new wording; tests assert those (section 6.1). Anchors are part of the checklist so grinch reviews them.
5. **Grinch gate.** In this exact order:
   - (a0) **Two-sided completeness gate (G1, binding):** grinch derives their own semantic inventory from the OLD text BLIND, before opening dev-rust's checklist, and commits it to the stage checklist file. The two OLD-side inventories are diffed first; every row present in only one list is a finding to reconcile before wording review. Only then are the mapping table and new text read.
   - (a) Re-derive a semantic inventory from the NEW text blind, diff against the reconciled old inventory: every mismatch is a finding.
   - (b) Adversarial probing per row: "does the new text still forbid X / permit Y / bind Z exactly as before" including edge readings (does a cut sentence widen a grant by removing a qualifier?).
   - (c) Verify anchors are unique in the asserted scope (section 6.1's block-scoping rule), and re-grep ALL previously designated anchors from earlier stages for new duplicates introduced by this stage (G6).
6. **Measure** the text's rendered before/after chars via the harness (section 7); record in the stage checklist.

**Checklist artifact:** one file per stage, `plans/1005-s<N>-checklist.md`, containing the per-text inventory + mapping tables + anchors + em-dash constraint map + measurements, plus grinch's blind OLD-side inventory (committed before the mapping table is read, per 4.5(a0)). Written by dev-rust during implementation, marked up by grinch, referenced by my verdict. Example row format:

```
| # | Class | Old statement (condensed) | New carrier (quote or DROPPED ref) |
| 3 | RULE  | never modify/delete a message file once written | "Never modify or delete a message file once written." |
```

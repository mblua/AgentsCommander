## Lock order and ownership

Order: operation turn -> short-lived settings snapshot/session-list read -> process-local JSON mutex -> per-file OS sidecar -> read/mutate/publish -> release both synchronous guards -> coordinator restart submission -> await settlement -> final classification/snapshot -> release turn. Settings/session guards are dropped before waiting for turn or submitting lifecycle. No Matrix and replica sidecars nested; no team-config guard during replica write. Never take the turn from coordinator worker, restart_session_inner_with_intent, or a worker callback. Worker submits no recursive job; existing IN_SELECTION_WORKER rejection remains.

restart_session_inner_with_intent merely delegates to SelectionCoordinator::restart_lifecycle. Worker is sole lifecycle owner. Do not replace coordinator or add parallel restart executor. A response receiver disappearing cannot cause early guard release while accepted job still runs. No timeout wrapper may drop a restart future and continue/unlock; maintain await until reply or provable worker termination. Existing coordinator shutdown drains queued jobs as unavailable and finishes active execute_envelope before next cancellation check. Any newly discovered background restart continuation must be joined/drained before turn release and reviewed before code acceptance.

## Snapshot, identity, ordering and error rules

Fingerprint = lowercase SHA-256 of a serde-serialized tuple, schema tag `selection-lock-v1`; typed tuples/BTreeMap only, never unordered maps. Assignment tuple includes operation, canonical anchor + Matrix identity, scope, normalized requested pair, restart choice, decision, sorted canonical candidate membership, and for each candidate persisted pair/flag/invalid marker plus sorted live session IDs with selected provider/profile identity. Include eligible membership. Generate separate hashes for each offered conflict decision. A no-conflict direct hash binds decision null. Removal binds only its operation/scope/anchor/candidate pair+flag+identity state; it has no session operation. Default hash is separate domain `replica-selection-default-v1`.

A client echoes only the fingerprint for its chosen decision; server reconstructs scope and targets using configured roots and strict canonical origin identity, never trusts eligiblePaths returned by a client. Re-enumerate under the shared operation turn and compare before any writes; pair, flag, membership, anchor identity and relevant restart session changes invalidate old approval. Return stalePreview with no side effects if prevalidation fails. Do not auto-resubmit force after refresh. Legacy no-fingerprint ordinary replica apply remains permitted, but all bulk, new assignAndLock and removal operations require current preview confirmation.

Candidates with invalid protection state have explicit errors and no write/restart. For an invalid identity whose Kind membership cannot be proved, retain enumeration diagnostics and mark scope totals incomplete; fail scope-wide force/unlock certification rather than assuming exclusion. Anchor invalid/unreadable fails the operation. Do not flatten directory iteration errors silently. Before each write compare expected pair/flag and strict identity inside the OS guarded callback. A later target race yields per-target stalePreview; earlier writes remain committed and accurately reported. Never expand force membership. Unrelated metadata updates do not stale a reviewed pair.

Extend `coding_agent_profile_selection_updated` with operation?:"assign"|"assignAndLock"|"unlock"|"default", affectedPaths?:string[], removedCount?,newlyProtectedCount?,skippedLockedCount?. Keep existing assignment scope/provider/profile/count fields and old individual events. Unlock emits scope + affectedPaths + removedCount, no pretend assignment. Default emits scope:"default", operation:"default", agentPath:matrixPath, affectedPaths:[], and actual default. Registered transports emit/broadcast the same returned payload. Existing sidebar event reload remains valid; active modal refreshes its own previews/default after each successful or partial operation and on external selection event, clearing stale decisions.

Backend operation owns completion: dispatch rejects worker-task reentry BEFORE spawning, then spawns one owned task carrying cloned handles and acquires the turn inside that task; caller await may disappear without cancelling work. No Cancel RPC is introduced. Dialog Cancel/Escape before apply sends nothing. After submit, the promise resolves only when all initiated lifecycle jobs have completed, with persisted/restart outcomes. UI closure/disconnection does not drop ownership. Never timeout by dropping a coordinator reply receiver while its job can still mutate sessions; cancellation/timeout may be reported only after the coordinator job has actually settled. Shutdown terminates the process or drains accepted work using existing lifecycle shutdown; a live process must not acknowledge subsequent unlock while prior work can restart later. The implementation must prove these boundaries with barriers and worker failure cases before acceptance.
